# 辅助开发协作约定

本文件记录项目的工程边界，适用于使用 AI 编程代理的贡献。它不替代 [贡献指南](../../CONTRIBUTING.md) 或仓库分支规则。

- 先检查工作区、现有模式和相关规格，不覆盖无关改动。需求优先级为 PRD、数据库设计、模拟支付设计；三份文档见 [spec](../spec)。
- 不重新设计已验证的十张核心表来适配框架默认字段。账户使用 username/password_hash，普通注册只能建立患者；资料和账户同事务创建。
- 预约生命周期统一按患者 → 科室 → 医生 → 排班 → 号源 → 预约 → 订单 → 退款保护资源。管理入口不能反向获取患者锁，按需回收在创建事务外逐条执行。
- 锁后使用服务端 UTC 时间；展示为医院时区；半开区间、15 分钟上限、金额快照和历史关联不变。
- 待支付未回收、已确认和已完成均占号。取消/过期只释放一次，付款不二次占号，完成不释放；退款失败不恢复预约。
- 停诊只影响新增预约及待支付付款，既有预约逐项处理。管理员核实后才能登记完成。
- 演示只用合成数据和 MOCK_WECHAT，明确无实际扣款。演示初始化可在首次本地启动显示新生成的随机登录凭据；不把凭据写入公开资料或 CI 日志，不重置既有密码。
- 常驻 HTTP 进程不持有 DBA 权限。迁移、测试和恢复使用隔离入口；不关闭权限边界解决普通环境错误。
- 改动应保持聚焦，外部输入在入口校验，不为理论边界提前增加抽象。关键测试使用真实 MySQL 和独立进程/连接，不以顺序请求冒充竞争。
- 运行实际质量、静态分析、构建和相应回归；如未运行，明确标记。不能删除有效检查换取通过，不把测试计划写成测试结果。
- 不提交 `.env`、凭据、真实资料、数据库转储、会话、敏感日志或构建产物。性能与恢复实验只能在独立库进行，不覆盖已有业务数据。
- 变更通过功能分支和 PR 复核；遵守实际仓库保护规则。代码、截图和文档结论都需要可核对的依据。
