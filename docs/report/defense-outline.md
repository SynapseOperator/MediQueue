目标约6分30秒。只演示合成资料，始终明确“模拟微信支付／无实际扣款”。事实依据为[课程报告](MediQueue-course-report.md)与[AC矩阵](../verification/p6-acceptance-matrix.md)；性能、恢复和CI只引用已取得的最终证据。

## 上台前

按[Windows演示指南](../windows-demo.md)启动正确MySQL、PHP和调度器，检查`/health`；启动器`-CheckOnly`可读状态。本机已实测MySQL/应用停止后恢复、数据摘要不变、调度器实际执行，但未重启Windows且不是开机服务。可用`php artisan mediqueue:demo-scenario <新前缀>`建立独立虚构场景，隐藏输入密码，不放报告、终端历史或投影。选择尚未开始的合法时段，不删旧预约或改占用腾空。预打开ER图、预约详情、退款、统计及P6性能/恢复记录；图片备用须说明为历史真实截图，不假装实时操作。

## 0:00—0:35：题目与范围

“MediQueue用PHP/Laravel与MySQL实现单医院多科室预约。每时段有多个名额；患者预约、医生只读、管理员维护和逐项处理异常。没有微信商户资质，因此付款退款仅本地模拟，无真实资金。”

展示首页，指出核心是名额、时间冲突、订单和状态一致。

## 0:35—1:25：模型

沿ER图讲医生→排班→号源→预约→订单→退款。排班是一次出诊，slot是其中可售区间，故分表；十张核心表之外的sessions/migrations为技术表。UNIQUE保证最多一个订单，同事务建立才保证成功必有一个。费用为历史快照，occupied_count为可核对冗余，历史科室取schedule。

## 1:25—2:35：患者主流程

选择未来时段→确认本人/金额→创建→模拟付款成功→查看CONFIRMED/PAID→开始前取消。说明退款先PENDING，未宣称到账；管理员另处理。实际截止取15分钟和开始较早者，过期资格不等清理器。

若现场无合适名额，使用[P5确认图](../verification/screenshots/p5/confirm.jpg)和[收银台图](../verification/screenshots/p5/payment.jpg)，明确历史截图来源。

## 2:35—3:40：并发与异常

展示锁序与JSON：20独立进程/连接争最后1号，1成功19拒绝。不是开两个网页认定并发。

“不同slot不共享slot锁，所以跨医生冲突要先锁患者。条件占号、预约、订单、审计同事务；任何一步失败全部回滚。取消/过期只释放一次，付款不二次占号，完成保留消费。”

未知提交先查原键或原记录，不换编号盲重放。测试使用的受控时钟与异常注入如实说明。

## 3:40—4:30：管理、医生与统计

展示退款FAILED后沿原记录重试成功；医生本人只读名单。停诊不批量取消，完成需人工核实。指出统计创建日期和就诊日期不同，退款按成功时间，净额全为模拟。容量先按slot聚合，避免被多条预约JOIN放大；账实差异显示待核对，不自动修数。

## 4:30—5:30：性能与恢复

引用[性能实测](../performance/p6-report.md)：5万预约/订单、100患者各500条、1000时段；预热后7次，中位到期查询0.3130ms，对照9.0846ms。实际八表历史页面2.4467/2.4713ms且没有用created_at索引，不能套简化查询收益。全部是均匀待支付未回收数据，未测写入和空间；不把cost当毫秒。

展示[恢复证据](../verification/p6-backup-results.json)：12表全行哈希一致、2视图/2例程、孤立/金额/容量差异0；恢复库预约9真实完成付款→取消→退款失败→原记录成功，源库摘要不变。强调不是只生成SQL文件，也未清空原业务库；同机演练不代表异地灾备。

## 5:30—6:30：验收与边界

展示最终JUnit、最新PR四项CI、AC矩阵。本地已实测234测试/2939断言/0失败；远端只引用当前提交真实结果。并发分支会使不同运行断言数略有差异。AC-22是条件不适用，不是“真实支付通过”。

“本项目证明课程范围的数据库一致性与可复现，不是医院生产SLA或安全测评。未来真实支付需独立设计验签和异常补偿，当前不为它扩张基础设施。”

## 常见追问

| 问题 | 回答要点 |
|---|---|
| 完成为什么不释放？ | 已消费历史名额，统计口径含COMPLETED。 |
| 过期未清理占号吗？ | 仍占，付款已失效；实际回收事务后才减一次。 |
| 为什么不设patient+slot唯一？ | 取消后允许新键再约，旧历史必须保留。 |
| 改价会改旧账吗？ | 新建复制DECIMAL字符串到预约/订单，之后仅改现价。 |
| CHECK能防重叠吗？ | 不能跨表查询其他预约；由患者锁后的区间查询判断。 |
| 保证绝无死锁吗？ | 不保证；统一锁序、短事务、三次完整重试与真实锁超时测试。 |
| 退款失败怎么办？ | 原ID/编号/金额保留，重试原行，成功不回退。 |
| 视图自动验身份吗？ | 不会；INVOKER不等于行级授权，应用仍检查角色与归属。 |
| 真微信支付吗？ | 不是，没有商户、真实码、验签或资金。 |
