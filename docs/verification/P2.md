## 功能与证据

| 用户要求 | 实现与实测证据 |
|---|---|
| 注册事务一致性 | AuthFlowTest：users/PATIENT、patients、白名单 audit 同事务；注入审计异常后全部回滚；大小写重复账号拒绝 |
| 登录、退出、会话失效 | AuthFlowTest：正确/错误密码；真实加密 cookie 与 MySQL sessions；登录更新 ID；退出后原会话不可继续使用；改密、账号停用后旧会话拒绝 |
| 角色与本人资料 | AuthFlowTest、DirectoryAndWorkbenchTest：公开注册拒绝身份升级；服务端角色路由拒绝；患者只读写自己档案；伪造 URL/请求身份不能访问他人资料 |
| 医生只读 | DirectoryAndWorkbenchTest：本人排班与时段可见，其他医生排班 404，患者/管理员不能进入医生私有工作台，医生资源写入 403 |
| 管理员资源管理 | HospitalResourcesTest：科室、医生账号和档案、排班、号源合法写入；医生或科室停用、账号停用与上层状态校验；管理审计失败回滚 |
| 时间与历史 | 半开区间相邻允许、部分重叠拒绝；业务日期与上海时区转换；不跨日、不越父区间、不新建过去时间；预约引用或已开始的时间身份不可改，容量不能低于占用且开始后冻结 |
| 停诊与费用 | 合成 PENDING_PAYMENT/UNPAID 历史 fixture 在停诊及恢复前后全部保留，截止、占用不变；号源改价不改预约金额快照；未实现 P3/P4 生命周期 |
| CSRF 与限流 | AuthFlowTest 显式关闭框架单元测试 CSRF 绕过，缺失 token 被拒；正确 token 可用；真实管理方法校验角色；登录与注册限流生效 |
| 演示凭据 | DemoCredentialsTest：限定 local/demo/testing、已有演示账号、隐藏密码输入、不接受非交互密码参数、不覆盖/清空业务数据，旧 session 删除，审计不含密码 |
| 公开页面与错误回显 | DirectoryAndWorkbenchTest：开放状态、日期窗口、开始边界、XSS 转义与隐私字段；非法数组或缺失字段返回错误表单仍为 200，旧输入不污染其他管理表单 |
| 管理并发 | ResourceConcurrencyTest：两个独立 PHP 进程、不同 MySQL CONNECTION_ID，同步竞争首个资源行锁；同医生重叠排班及同排班重叠时段各恰一项成功，仅一条资源及一条审计提交 |

原 P0/P1 的 100 项有效测试继续运行。P2 新增 59 项认证/CLI、页面/权限、资源规则及双进程竞争测试。所有 SQL 约束测试连接真实 MySQL；未使用 SQLite。

## 已知边界与 P3

- 本机原生 MySQL 为独立数据源且不设 Windows 自动启动服务；重启方式和 Docker/原生环境选择见 README。Docker 原数据保留，启动配置尚未修复。
- 不提供密码邮件找回、生产管理员开通或账号管理后台；当前受控初始化和演示密码工具只允许明确的演示环境。
- 管理页面采用小规模资源列表与折叠表单；公开目录已分页。当前科室排他锁便于证明正确性，后续有实际数据规模和执行计划后再优化。
- P3 应先实现患者→科室→医生→排班→号源的统一预约事务、请求幂等和金额快照，再验证 20 位独立患者争最后名额、同患者跨医生重叠及故障回滚。P2 管理并发不代替这些测试；付款、取消、到期和退款仍属 P4。
