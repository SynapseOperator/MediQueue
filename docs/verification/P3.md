## 真实并发

AppointmentConcurrencyTest 使用 Symfony Process 启动独立 PHP/PDO，父进程锁门闩与 stdin 信号保证竞争重叠。每场景验证 PID 和 CONNECTION_ID 均不同；失败必须为 slot_id 业务拒绝，不能用重试耗尽假装正常竞争失败。

| 场景 | 本地最终结果 | 一致性 |
|---|---|---|
| 20 位不同患者争最后一号 | 20 PID / 20连接；1 created、19 rejected | occupied=capacity=1，预约/订单/成功审计各1，无孤立订单 |
| 同患者跨两科室的不同医生重叠 | 2 PID / 2连接；1 created、1 rejected | 仅1预约及订单，受影响号源占用与实际记录相等 |
| 管理员先取得科室锁并停诊 | 2 PID / 2连接；1 suspended、1 rejected | 预约/订单/预约审计均0，停诊审计1，占用0 |
| 预约先取得科室锁并提交 | 2 PID / 2连接；1 created、1 suspended | 先有合法预约，随后停诊，预约/订单及占用保留，不批量取消 |

后两项由已取得真实行锁后的 QueryExecuted 事件暂停领跑进程，让另一进程进入同一锁请求，再释放；不依赖调度碰巧产生某种顺序。所有场景用单条 SQL 关联聚合核对 slot 占用与 PENDING_PAYMENT/CONFIRMED/COMPLETED 数量，差异均0，计数未超容量，未产生退款。

证据位于被忽略的 `test-results/appointment-concurrency-last-seat.json`、`same-patient.json`、`suspension-first.json`、`appointment-first.json`（后三个文件名同样以 `appointment-concurrency-` 为前缀）。文件含合成ID、进程/连接ID、结果及最终账实核对，不含凭据；每次场景先移除其旧文件，仅成功断言后重写。CI 与全套测试一起实际执行，并上传至 `mysql-junit` artifact。
