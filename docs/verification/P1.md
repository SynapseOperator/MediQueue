## 测试证明的内容

保留 P0 的 19 个用例并扩展回滚测试以覆盖全部迁移；新增 81 个用例，包含数据提供器展开后的场景。

- 实际表集合、字段类型和精度、非空时间、存储引擎、外键规则、唯一键和必要预约索引。
- 15 个外键逐一拒绝孤立引用（1452）；关联历史阻止父记录删除或主键更新（1451）。
- 唯一键重复拒绝（1062），订单/退款的一对一上限；同患者大小写及尾空格不同的请求键可分别保存，同键在其他患者下可用；取消后同患者、同号源可用新键保存另一条记录。
- 容量正数、占用不为负且不超容量、不能降至占用数以下；费用为正、两位小数往返、最大值 99999999.99、溢出拒绝（1264），预约费用快照不跟随号源价格改变。
- 状态集合、截止时间、释放/取消/完成/支付事件字段、模拟渠道和真实渠道字段恒为空；违法数据触发 CHECK（3819），必填 NULL 触发 1048。
- 全部合法预约、订单与退款状态均可保存；从合法状态单字段变异检查关键事件字段，断言具体 CHECK 名称，避免被无关约束失败遮盖。
- SYSTEM 审计可以没有操作者，也可引用有效用户；USER 必须有操作者。没有将“可为空”收紧成“必须为空”。
- Seeder 的医院次日到 UTC 换算、合成资料和关联、重复执行拒绝且不覆盖已有占用、生产环境即使 `--force` 仍拒绝、注入异常后全部种子写入回滚。

数据库 fixture 直接写入合法本行状态只用于验证表结构，不代表实现了任何业务状态转换或支付闭环。

## 边界与下一阶段

FK 保护引用完整性，不是完整的禁止历史删除策略；唯一键只证明至多一条，不证明注册必有档案或预约必有订单。CHECK 不实现跨表金额相等、角色匹配、区间重叠、`min(created_at + 15 分钟, slot.starts_at)`、容量计数与预约集合相等、权限或合法转换。这些仍需后续事务服务及并发测试。

P2 下一步为认证、角色与权限边界；P3/P4 才实现预约、支付、取消/过期/完成及退款闭环。本阶段未开展并发竞争、压力性能、备份恢复验收，也未接入真实资金。
