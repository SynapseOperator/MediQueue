# MediQueue 界面改版：参考来源与验收要点

日期：2026-11-17。范围：纯前端体验升级，不更改 Laravel Session/权限、预约事务、模拟支付、MySQL 结构或统计口径。本改版先进入独立 PR；远端 CI 只能证明构建和功能回归，**不能代替真实浏览器视觉验收**。

## 调研参考（仅借鉴体验，不复制项目代码或素材）

参考项目的功能和权限与本项目不完全相同。**不引入在线诊断、医生评分、头像、实时床位或真实微信支付，也不转为 Vue/React 前端。**

## 从 P6 真实截图发现的问题

- 390px 视口的导航跨多行，首页可操作空间被挤占。
- 医生时段在窄屏上是六列表格，需横向滚动才能看到预约动作。
- 首页文字与卡片的视觉权重相近，患者主动作不够突出。
- 管理看板九项指标在相似卡片中平铺，难以第一眼确定重点。
- 预约确认与支付内容较密，金额与下一步操作不够醒目。

## 本轮设计原则

1. **患者任务优先**：首页找医生为首要动作，医生详情用日期+时段卡片，不再需要横向滚动完成预约。
2. **渐进披露**：手机导航采用原生 `details/summary` 折叠，保留全角色服务入口，不依赖额外 JS。
3. **真实数据**：不造医生照片、评分、空有可用时段或支付成功数据；展示内容来自当前服务器。
4. **可访问性**：可键盘操作的菜单、可见焦点、标注表单、足够大的触控目标，支持 reduced motion。
5. **可维护性**：共用 `resources/css/app.css` 的设计变量和组件；不复制整套外部设计系统。
6. **清晰业务边界**：模拟微信付款和退款始终醒目标注“无实际扣款”，页面只展示服务端真实状态。

## 本轮改动

- 统一背景、配色、按钮、表单、卡片、空状态与响应式组件。
- 重做 PC 导航和 390px 折叠菜单。
- 重做首页 Hero、预约流程、科室卡片与角色服务介绍。
- 重做医生目录的卡片与科室筛选。
- 把医生详情的出诊列表由横向表格改为响应式时段卡片，保持 GET 预约确认入口和幂等请求键不变。
- 预约确认增加步骤标识与费用摘要，模拟收银台突出金额、资格反馈与演示说明。
- 管理指标增加主次层次及模拟财务区分，不修改统计 SQL。

## 必须人工核对（本 PR 的发布门槛）

- 视口：桌面 1440px、平板约 768px、手机 390px，以及最小 320px；无遮挡、无横向溢出。
- 登录状态：访客、患者、医生、管理员；菜单、退出、角色路由、账户名不会溢出。
- 业务流程：科室 → 医生 → 时段卡片 → 预约确认 → 创建订单 → 模拟收银台 → 详情/取消/退款。
- 边界：无医生、无时段、时段售罄、错误回显、到期/停诊、支付结果未知、退款失败。
- 管理：统计概览/明细、排班表单、审计、管理员模拟退款；数据口径无变化。
- 可访问性：Tab 键焦点、菜单 summary 键盘操作、对比度、200% 放大。
- 对比截图：同一视口分别保存首页、医生目录、医生时段、预约确认、模拟支付、管理概览；只用合成数据。
- GitHub：`quality/mysql/frontend/secrets` 与此前全部真实 MySQL 测试通过；视觉验收完成后再由负责人决定合并。

本轮没有在远端重建真实运行页面或独立完成上述浏览器人工检查，因此不能声称“视觉验证已通过”。
