# ADR-0003：P2 认证与医院资源管理

- 日期：2026-11-17
- 范围：P2，基线 main `ec47a853bb7cebf11117fbec1d3006f509cefc19`
- 依据：PRD V1.1 FR-01/02/03、BR-01/03/05/07/11、AC-01/18/19/20/23；数据库设计 C-02/06/08/15、TX-06

## 复用既有结构

不修改 P1 migration、不重建业务表。只有 `User` 需要 Eloquent 认证模型；资源查询与短事务使用已有 Query Builder，不引入权限包、API token、前后端双工程或通用仓储层。

User 的认证密码列为 `password_hash`，毫秒写入格式匹配 `DATETIME(3)`，序列化隐藏密码哈希。不启用 remember-me，避免为框架默认行为新增 remember_token。身份仍来自数据库 `role/status`，不能从注册参数或页面按钮推导。

## Session 与入口校验

公开注册仅创建 PATIENT。用户名限制为 3–64 位 ASCII 字母、数字、下划线，去首尾空白、转小写后保存与登录；这与现有用户名 ai_ci 唯一比较一致，也用于登录限流键。不新增手机号唯一性或身份证字段。

密码至少 12 字符、最多 72 字节且不含 NUL，与当前 bcrypt 实际边界一致。医生创建、患者注册和受控 CLI 复用同一密码规则，数据库只写 Hash 哈希。表单不回填密码，审计不包含姓名、联系方式、密码、完整请求体。

登录使用 Laravel Session guard 和哈希校验，成功后更新 Session ID、CSRF token 并保存密码哈希会话基线；登出失效会话并更新 token。web 请求统一经过账号启用检查和 AuthenticateSession，改密后的旧会话不能继续使用。CLI 改密同时删除对应数据库 sessions；正在进行的旧请求即使随后写回旧会话，下次访问仍会因哈希不一致被拒绝。

登录按规范化用户名加 IP 每分钟 5 次，并按 IP 每分钟 30 次限流；注册按 IP 每分钟 5 次。使用现有文件缓存，适合当前单机单应用，不声称支持多实例全局限流。Laravel web 中间件负责请求伪造防护，测试显式开启其真实校验并使用数据库会话和加密 cookie。参考 [Laravel 认证](https://laravel.com/docs/13.x/authentication) 与 [CSRF 文档](https://laravel.com/docs/13.x/csrf)，实际行为核对当前锁定框架源码。

## 角色与对象权限

| 身份 | 服务端规则 |
|---|---|
| 访客 | 公开目录、患者注册与登录；不能访问私有路由 |
| PATIENT | 仅从当前 user_id 读取/更新唯一患者档案；忽略外来路由身份，拒绝请求中的身份/角色修改 |
| DOCTOR | 仅从当前 user_id 找医生档案，再以 doctor_id 限定排班详情；其他医生详情返回 404；没有修改路由权限 |
| ADMIN | auth/active/role 中间件限制全部资源管理方法；仅写入经过入口校验的白名单字段 |

角色中间件负责功能权限，SQL 归属条件负责具体对象。医生和管理员不因后台身份而获得患者的自助档案修改权限。没有开放预约、支付、取消、退款或财务信息路由。

医生在管理员页面创建，users(DOCTOR) 与 doctors 及管理审计同事务。管理员由有主机执行权限的人通过限定环境的隐藏输入命令初始化，不通过公开注册身份选项。`users.status` 控制登录权限，`doctors.status` 控制医生服务资源，两者独立；资源停用时历史只读工作台保留。

## 资源时间、历史与锁

排班和号源界面接收上海当地的 `datetime-local`，校验后转为 UTC 毫秒时间。排班必须在一个医院业务日期内且结束严格晚于开始。新建开始时间须在锁内当前时间之后；相邻区间允许，冲突查询为 `existing.starts_at < new.ends_at AND existing.ends_at > new.starts_at`。所有排班状态均占据其医生的安排区间，关闭不等于可以静默建立重叠安排。

草稿排班可先配置号源，公开查询只展示有效账号、有效医生/科室、OPEN 排班及未开始 OPEN 号源；默认窗口含今天在内 7 个医院自然日，可通过配置调整。公开输出选择展示字段，不返回账号哈希、内部停诊原因或患者资料。

管理操作使用短事务，按科室→医生→排班→号源取得父资源保护，冲突查询在锁后进行。科室当前使用排他锁，简单地串行化同科室管理操作；它的并发吞吐不是本阶段优化目标。锁内重新检验归属和资源状态，死锁仅重试整个事务，最多 3 次。管理代码不会在这些资源锁之后回头申请患者锁或执行预约生命周期。

排班医生和号源父排班不可编辑；有任何排班的医生本阶段不支持转科。这是规范“不做跨科自动迁移”的最小实现，不新增转科工作流。排班科室保留创建时快照，绝不随编辑同步改写历史。所有资源均无物理删除路由。

任意预约状态引用后，排班时间/日期/班次及号源起止时间不能改；缩短排班也不能排除已有号源。已开始排班/号源的时间身份冻结，号源容量按原始开始时间冻结，开始前新容量不能小于已占用数。价格只修改号源现价，不修改预约或支付金额快照。`occupied_count` 不接受管理请求写入。

停诊写 SUSPENDED、理由与审计，恢复不改预约或截止时间。未发布/停诊/关闭的资源不会被公开作为可用时段。没有以自动取消、重建预约或释放名额来实现停诊。关联账号或基础资源停用后，不能继续发布开放安排。

成功管理变更与白名单 audit_logs 同事务，失败回滚全部。审计用于追踪 ID、状态、时间、容量、价格等必要事实；不会复制医生完整介绍或患者联系方式。入口重复唯一键转为可读校验错误，不放宽数据库唯一约束。

## 演示凭据与限制

`mediqueue:demo-password` 仅允许 local/demo/testing 中六个既有 seed 账号，必须隐藏交互输入两遍密码，不接受密码命令行参数、不输出密码、不清空业务表。`mediqueue:create-admin` 同样只在限定环境中创建新账号，并拒绝覆盖已有用户名。生产部署的管理员开通与密码恢复不属于本次课程环境，未提供伪装成安全恢复的通用重置页面。

P2 验证仅证明认证与资源管理。双进程测试竞争真实 MySQL 行锁，验证重叠管理写入仅一个提交；不代表 P3 的 20 人抢号、同患者跨医生冲突或 P4 的付款/取消/到期竞争已实现。真实测试结果见 [P2 验证记录](../archive/verification/P2.md)。
